## 3. 自動測試梯次

### 每次提交

```powershell
npm test
```

必須通過單元測試、UI 流程、30 人復原、婚禮操作回歸及 preflight 13/13。

### 婚禮前一週

在第二台電腦對 DigitalOcean 執行下列測試。每次測試前都必須確認狀態為 `LOBBY`。

```powershell
npm run stress -- --url https://YOUR_DOMAIN --clients 30 --tapRate 5 --answerRate 0.98 --maxSeconds 720 --report reports/stress-30.json
npm run stress -- --url https://YOUR_DOMAIN --clients 75 --tapRate 5 --answerRate 0.98 --maxSeconds 720 --report reports/stress-75.json
npm run stress -- --url https://YOUR_DOMAIN --clients 150 --tapRate 5 --answerRate 0.98 --reconnectClients 15 --reconnectAtQuiz 5 --maxSeconds 720 --enforceDuration true --report reports/stress-150.json
npm run stress -- --url https://YOUR_DOMAIN --clients 180 --tapRate 5 --answerRate 0.98 --maxSeconds 720 --report reports/stress-180.json
```

150 人是正式發布門檻；180 人用來確認至少 20% 的人數餘裕。30 與 75 人用來確認人數較少時賽道估算不會讓遊戲過早或過晚結束。

### 147 個模擬玩家加 3 支手機

先在第二台電腦執行：

```powershell
npm run stress -- --url https://YOUR_DOMAIN --clients 147 --manualHost --expectedTotalPlayers 150 --tapRate 5 --answerRate 0.98 --reconnectClients 15 --reconnectAtQuiz 5 --manualStartTimeoutSeconds 1800 --maxSeconds 720 --enforceDuration true --report reports/manual-host-150.json
```

看到 `READY` 後才讓三支手機掃碼。控制台總人數顯示 150，再由操作員 A 正式開始。`--manualHost` 不會自動重置、開賽或在結束時清場。

## 9. 婚禮前 30 分鐘 Go／No-Go

```powershell
$env:SERVER_URL="https://YOUR_DOMAIN"
$env:STAFF_ACCESS_CODE="1009"
npm run preflight
```

- [ ] preflight 為 13/13，狀態為 LOBBY。
- [ ] QR 不含 localhost，三支手機皆可加入。
- [ ] 投影為 16:9、100% 縮放與全螢幕。
- [ ] 已點啟用音效，現場音響可聽見 Ready 音。
- [ ] 三支手機完成選隊、點擊與鎖屏重連。
- [ ] 操作員 A 完成一次暫停與恢復。
- [ ] LAN 備援伺服器可開啟，Git commit 與正式站相同。
- [ ] 主持、技術人員知道 Node 重啟後必須重賽。
- [ ] DigitalOcean 與本機電腦電源、網路保持穩定。

以下任一情況必須判定 NO-GO：P0 未關閉、QR 無法供手機連線、玩家或隊伍資料錯亂、未完成 18 題、三題獎勵重複發放、重置失效、投影無法恢復、音響無替代方案，或 LAN 備援未準備完成。
