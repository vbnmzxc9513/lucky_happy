## 3. 測試矩陣

### A. 每次提交的自動回歸

執行 `npm test`，必須全部通過：

- 地圖 10 個關卡順序與快隊補觸發。
- 五隊建立、50 人上限、自動分隊與換隊失敗保留原隊。
- 多數決、同票、未作答、重複作答和暫停倒數。
- 終極衝刺、20 次爆擊、10 題完賽守門與四個獎項。
- 投影、手機、控制台和出題後台的主要 UI 狀態流程。

### B. 賓客手機端

裝置至少包含 iPhone Safari、Android Chrome，以及 320x568、360x800、390x844、430x932 四種尺寸。

1. 空白暱稱、20 字上限、表情符號與特殊字元。
2. 五隊選擇、換隊、滿隊、倒數結束自動分隊。
3. 高速連點、20 次爆擊、排行與進度更新。
4. 四選一答題、送出鎖定、答對／答錯／團隊結果回饋。
5. 鎖屏、切到背景、重新整理、Wi-Fi/行動網路切換後恢復。
6. 比賽開始後陌生新加入必須被拒絕，原賓客必須可重連。

### C. 主持與投影

在 1280x720、1366x768、1920x1080、3840x2160 且瀏覽器縮放 100% 測試。

1. 大廳 QR、規則、選隊、賽道、答題、暫停、終極衝刺與頒獎全流程無捲動。
2. 投影端不顯示任何操作按鈕；控制台可開始、暫停、繼續與切換畫面。
3. 比賽結束前不得進入或揭曉頒獎；四獎依序揭曉且保留神秘文字。
4. 得獎同分時依答題速度決勝，錯題王不包含完全未作答者。
5. 主持投影在答題中重新整理後，題目與剩餘時間必須恢復。

### D. 網路、離線與復原

1. 執行 `npm run preflight`，結果必須為 `13/13` 且狀態為 `LOBBY`。
2. 執行 30 人復原測試，所有人加入、滿隊、斷線、答題鎖定與重置均通過。
3. 完全拔除 WAN，只保留 LAN；重新開啟所有頁面並用真實手機掃 QR 完成一局。
4. 模擬主持頁重新整理、10% 手機同時斷線、網路延遲 200ms 與短暫丟包。
5. 演練 Node/VPS 重啟；確認工作人員知道必須回大廳重賽及切換 LAN 備援。

### E. 150 人壓力與時間

正式版在 DigitalOcean 與本機 LAN 各跑一次完整 10 題賽事：

```powershell
npm run stress -- --clients 150 --tapRate 5 --reconnectClients 15 --reconnectAtQuiz 5 --maxSeconds 600
```

通過門檻：

- 150/150 成功加入，意外斷線與系統錯誤皆為 0。
- 15/15 強制斷線玩家成功恢復，答案不可重複提交。
- 10/10 題目開始並結算，四個最終獎項完整產生。
- 全場時間 6:30 至 8:30；HTTP P95 < 250ms、投影更新間隔 P95 < 100ms、事件迴圈延遲 P95 < 50ms。
- 另以 180 人完成一局 10 題容量測試，沿用相同門檻，確認有至少 20% 現場餘裕。

- P0 必須為 0；P1 必須修正或由婚禮負責人書面接受風險。

### 建議節點

1. 現在：修正兩個 P0 與三個 P1，補上對應自動測試。
2. 婚禮前 7 天：凍結題庫與設定，在 VPS 和 LAN 各跑完整壓測。
3. 婚禮前 2 天：場地實測投影、音響、QR、實機手機與網路切換。
4. 婚禮前 30 分鐘：執行 preflight、兩支手機掃碼與一次暫停／恢復演練。
